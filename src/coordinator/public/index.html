🤖 Simulación de Casos miniServer (Worker)

El archivo miniServer.js ha sido mejorado para soportar Redirección al Líder y Recuperación de Fallos (Failover). Aquí te explicamos cómo probar los escenarios principales.

Caso 1: El trabajador se conecta al líder

Simplemente inicia el miniServer apuntando a la URL de este middleware (que asumes que es el líder). El trabajador se registrará y enviará pulsos correctamente.

node miniServer.js 4001 Worker1 http://localhost:4001 <TU_URL_DE_NGROK>

Caso 2: El trabajador se conecta a un seguidor y es redirigido al líder

Inicia el miniServer apuntando intencionalmente a la URL de un nodo Seguidor (Follower). El seguidor rechazará el registro con un código 409 Conflict y le indicará quién es el verdadero líder. El miniServer interceptará esto y se redirigirá automáticamente al líder correcto.

node miniServer.js 4002 Worker2 http://localhost:4002 <URL_NGROK_DE_UN_SEGUIDOR>

Caso 3: El líder cae y el trabajador se reconecta al nuevo líder

Una vez que el miniServer está conectado al líder actual, desconecta o simula la caída de ese líder usando el botón 🔌 Desconectar mi Nodo en la parte superior derecha.

  • El clúster hará una elección y escogerá un nuevo líder.
  • El miniServer detectará que sus pings fallan (o reciben un error del servidor caído).
  • Automáticamente, el miniServer revisará su lista interna de peers conocidos, escogerá uno al azar e intentará registrarse allí.
  • Si ese peer resulta ser el nuevo líder, lo aceptará. Si es un seguidor, se ejecutará el Caso 2 y lo redirigirá al nuevo líder definitivo.
